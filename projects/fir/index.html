Configurable FIR Accelerator

A 32-tap streaming FIR accelerator designed to keep signed arithmetic and sample order correct under backpressure.

01 — What I Built

I designed a streaming FIR accelerator in Verilog with a parallel multiply-accumulate pipeline, FIFO buffering, and software-programmable coefficients. AXI4-Stream carries the samples and results; AXI4-Lite configures the filter without a register transaction for every sample.

The main integration problem was keeping arithmetic, sample history, and valid bits aligned when the downstream consumer stops accepting data. The design holds pending work and resumes in order when capacity returns.

y[n] = Σ h[k] × x[n − k],  k = 0…31

02 — Parallel Datapath

Thirty-two signed multipliers feed five registered reduction levels: 32 → 16 → 8 → 4 → 2 → 1. A multiplication stage followed by the five sum stages allows a new dot product to enter on each available clock. Compared with a time-shared MAC, this spends more multipliers and registers to increase throughput.

Tap zero uses the current FIFO sample; the other taps use stored history. The history shifts only on samples_valid AND samples_ready, so input gaps and pipeline stalls do not change the sample sequence. Reset clears the history, defining zero-valued samples before the start of the stream.

A signed 16 × 16-bit product requires 32 bits. Summing 32 full-range products needs up to 37 signed bits; the 40-bit accumulator provides additional headroom. The output retains the wide sum without saturation or rounding. Its binary point follows the input and coefficient scaling.

03 — Backpressure & Data Integrity

A transfer occurs only when valid and ready are both high at a clock edge. The input and output FIFOs absorb temporary differences in rate. When the output FIFO cannot accept a pending DSP result, the whole arithmetic pipeline holds its data and valid bits together.

pipeline_advance = !result_valid || result_ready

result_ready describes capacity in the output FIFO, rather than the external consumer directly. Once buffering fills, the DSP stops accepting samples, the history holds, and backpressure eventually reaches s_axis_tready. A blocked valid output must keep its data stable until the consumer accepts it.

04 — Coefficient Configuration

Software writes 32 shadow coefficients, commits the bank, then enables the stream. A commit copies all shadow coefficients into the active bank on one clock edge, avoiding a partially programmed filter. A later shadow write has no effect until another commit.

The write interface captures address and data independently, allowing either AXI4-Lite channel to arrive first. Byte strobes update the selected coefficient bytes. The block supports one outstanding write response and one outstanding read response.

Disable does not clear sample history or discard pending outputs. For a clean configuration boundary, software must stop sending samples and drain queued work before committing. Samples already multiplied retain their earlier coefficient set.

05 — Verification Strategy

Separate testbenches exercise the FIFO, DSP, and integrated accelerator. The top-level checker maintains its own sample history and signed dot-product model, queues expected outputs in order, and compares results on output handshakes. It checks transactions rather than assuming a fixed wall-clock latency.

The integrated test programs and reads back all coefficients, commits them, then changes a shadow coefficient without committing. It sends 80 signed samples with signed coefficients through a deliberate 30-cycle output stall, followed by randomized output readiness. Every accepted result must match the committed bank; a separate check requires valid and data to remain stable across blocked output clock edges. It also checks that input readiness is low while disabled.

These tests provide directed and randomized functional checks. The current integrated driver presents write address and data together; independent arrival and prolonged AXI read-response stalls need additional protocol tests before claiming comprehensive interface coverage.

Vivado 2025.2 synthesis for xc7k70tfbv676-1 reports 1,915 LUTs, 3,793 flip-flops, 32 DSP48E1 blocks, and no block RAM. Post-route internal timing meets the 8.000 ns (125 MHz) clock constraint with +2.020 ns setup slack, +0.069 ns hold slack, and zero failing setup or hold endpoints.

One sample per cycle corresponds to a peak capacity of 125 million samples/s after pipeline fill. Sustained throughput depends on input availability and output readiness. Implementation timing is separate from the RTL testbench clock and does not demonstrate a board measurement.

Check Timing reports no missing clocks and no unconstrained internal endpoints. External I/O timing is not constrained: 106 inputs and 66 outputs lack delay budgets. These results establish internal timing closure; interface timing must be checked against the eventual integration target.

07 — Engineering Tradeoffs

I chose a parallel datapath for throughput, a registered tree to shorten combinational paths, and a global pipeline hold to keep backpressure behavior explicit. Shadow coefficients separate software updates from active filtering. The tradeoffs are additional arithmetic resources and buffering, plus software responsibility for managing configuration boundaries.

The current top level wires 32 explicit tap ports, so NUM_TAPS is not a general tap-count scaling interface. There is no clock-domain crossing, DMA engine, packet framing, or board-level demonstration in this project. The completed work focuses on synthesizable DSP arithmetic, stream control, memory-mapped configuration, and simulation-based verification.
