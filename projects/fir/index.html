Configurable FIR Accelerator

A 32-tap FIR datapath combining parallel arithmetic, programmable coefficients, and stream backpressure.

01 — Overview

I separated coefficient configuration from the sample stream: AXI4-Lite controls the register bank, while AXI4-Stream carries samples and results. That lets the arithmetic pipeline operate without a software transaction for every sample.

A synthesizable fixed-point FIR accelerator with AXI4-Stream data interfaces, AXI4-Lite coefficient programming, FIFO buffering, and a fully pipelined parallel multiply-accumulate datapath.

y[n] = Σ h[k] × x[n − k],  k = 0…31

02 — Datapath Architecture

The adder tree reduces 32 products to 16, 8, 4, 2, and finally one sum. Registers between the levels break the arithmetic path into shorter stages. This costs more registers and multipliers than a time-shared MAC, but allows a new dot product to enter on every available cycle.

The newest FIFO sample connects directly to tap zero. The remaining taps use stored history, and that history shifts only when the DSP accepts the sample. Shifting on every clock would corrupt the filter state during a stall.

Samples and coefficients use signed two’s-complement arithmetic. A 16-bit by 16-bit product needs 32 bits; adding 32 products needs additional headroom. The 40-bit datapath keeps the sum wide through the tree and exposes that result without a narrow output conversion. A specific fixed-point binary point is determined by how the input samples and coefficients are scaled.

A 32-sample delay line feeds 32 parallel signed multipliers and a five-level registered adder tree. The current input is used as x[n], avoiding an artificial leading-zero output. Under no stalls, the DSP accepts one sample per clock and the result reaches the output FIFO six clocks after the corresponding delay-line/DSP transfer.

03 — Flow Control

The DSP advances when its output is empty or the output FIFO can accept the current result: pipeline_advance = !result_valid || result_ready. If a valid result is blocked, every arithmetic stage and its valid bit holds. Input readiness falls at the same time, so the delay line cannot consume a new sample while the pipeline is frozen.

An output stall does not immediately stop external input: the FIFOs first absorb the difference in rate. Once their capacity is exhausted, backpressure reaches the source. This preserves the sample order without overwriting a pending result.

Input and output FIFOs decouple the external stream from the arithmetic pipeline. Ready/valid handshakes transfer data only when both signals are asserted. Backpressure propagates from output to input, holding pipeline data until downstream capacity is available. The FIFOs support simultaneous push and pop.

04 — Coefficient Programming

A shadow bank prevents a sequence of software writes from exposing a partially updated coefficient set. All active taps change together at commit. Samples already in the arithmetic pipeline have already been multiplied; future accepted samples use the new bank. If a clean boundary between filter configurations is needed, software must also manage the stream and drain pending work.

AXI4-Lite writes update shadow coefficient registers. A software-controlled commit copies the full shadow bank into active coefficients atomically. Software writes the desired coefficients, issues COEFF_LOAD, then enables processing.

05 — Verification

The top-level testbench maintains its own delay history and calculates an expected signed dot product for each accepted input. It compares each accepted output against the next expected value. The reference model follows handshake events rather than assuming a fixed number of clocks, which allows the same checker to work when output readiness changes.

The integrated test sends 80 samples with positive and negative values and coefficients. It also checks that input readiness stays low while disabled, reads coefficient registers back, commits the bank, and changes a shadow coefficient without committing it. Filtering should still use the previously committed coefficients.

Self-checking tests cover the FIFO, DSP datapath, and integrated accelerator. The end-to-end stress test includes signed arithmetic and randomized output backpressure. Source files and simulation commands are available in the repository.

06 — Implementation Results

Positive setup slack means the implemented paths meet the requested 8 ns clock period under the constraints used for the run. I present 125 MHz as the target met by implementation. The one-sample-per-cycle figure describes pipeline capacity after filling; input gaps and downstream stalls reduce sustained throughput.

Actual sustained throughput depends on stream availability and downstream readiness. The timing results come from FPGA implementation; the functional checks come from RTL simulation.

07 — Design Scope

The integrated top level supports 32 taps through explicit DSP sample ports. Signed accumulator width must be chosen for the intended input and coefficient ranges. The current design exposes a 40-bit output.
