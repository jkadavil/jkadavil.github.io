01 — Overview

A 32-bit RV32I processor implemented in Verilog, using a classic five-stage pipeline with data forwarding, hazard detection, control-hazard recovery, and byte-addressable memory. The design connects instruction execution with the pipeline controls needed to preserve correct architectural state.

I split the datapath into separate RTL modules so the ALU, register file, memories, pipeline registers, and control units could be checked independently. The integration work centered on keeping the instruction’s operands and control signals aligned as they crossed stage boundaries.

02 — Architecture

Each pipeline register carries more than an arithmetic result. It also preserves the destination register, instruction information, and write-enable signals needed by later stages. For example, a store’s forwarded data must arrive in MEM with the address and memory-write control for that same instruction.

Four pipeline registers separate fetch, decode, execute, memory, and writeback. Decode reads operands and generates control and immediate values. Execute performs ALU operations, signed and unsigned branch comparisons, and JAL/JALR target generation. Memory supports byte, halfword, and word accesses; writeback selects the ALU result, load data, or PC + 4.

Branches and jumps resolve in EX. Redirects flush younger instructions in IF/ID and ID/EX while allowing the redirecting instruction to continue, preserving jump link-register writeback.

03 — Data & Control Hazards

A dependency is only a hazard when the newer instruction actually reads the matching register. I pass source-use signals from decode into the hazard and forwarding logic. That matters for immediate instructions: bits in the immediate can occupy the rs2 field without representing a second register operand.

EX/MEM and MEM/WB results bypass the register file through forwarding multiplexers. EX/MEM has priority when both stages match, and store data participates in forwarding.

lw   x5, 0(x1)
add  x6, x5, x2

An immediate load-use dependency inserts one bubble: the PC and IF/ID register hold, while ID/EX is flushed. Source-use information suppresses false dependencies. The hazard and redirect paths control which pipeline registers hold or clear on the next clock edge.

04 — Instruction Support

Forwarding must select the value the older instruction will write architecturally. For JAL and JALR, that value is PC + 4 rather than the ALU result. Loads are excluded from the MEM-stage bypass because their load data is not the address calculated by the ALU.

Branch comparisons use forwarded operands, with separate signed and unsigned comparisons. JALR forms its target from rs1 + immediate and clears bit zero. LUI uses zero as its ALU base; AUIPC uses the instruction’s PC, so neither should accidentally consume a forwarded rs1 value.

Integer arithmetic, logical operations, shifts, signed and unsigned comparisons, LUI/AUIPC, byte/halfword/word loads and stores, six conditional branch types, and JAL/JALR. See the repository for the exact supported instruction list.

05 — Verification

Tests 1–3 print register results for inspection; tests 4–6 include explicit expected-value checks. Fibonacci and bubble sort exercise repeated dependencies and redirects, while the corner-case program isolates behavior that could be hidden by a larger program. Checking that wrong-path registers remain unchanged is especially useful: reaching the correct jump target alone does not prove that younger instructions were removed.

At PC 0xA0, lw x9, 0(x0) reads 55 from data-memory address zero. The following addi x27, x9, 1 at 0xA4 needs that result. The hazard unit holds the PC and IF/ID register for one cycle and clears ID/EX controls to insert a bubble, while the load continues through memory.

When the ADDI reaches execute, forward_a = 01 selects the load’s writeback value: ex_alu_input_a = 55. The instruction later writes 56 to x27. The preceding load at 0x98 and independent ADDI at 0x9C proceed without a stall, demonstrating that detection follows actual source-register use.

I used six directed programs: ALU operations; word loads/stores and a load-use hazard; Fibonacci; byte/halfword accesses; eight-element bubble sort; and pipeline corner cases.

The corner-case test checks branch outcomes, jump targets and link values, wrong-path flushing, upper-immediate forwarding, and genuine versus false load-use stalls. It expects one genuine stall and eight redirects.

06 — Synthesis Results

Asynchronous memory reads simplify this pipeline’s current timing model, but they map to distributed memory on this FPGA. Moving to synchronous block RAM would change when instructions and load data become available, so it requires changes to the pipeline controls as well as the memory modules.

07 — Design Scope & Next Steps

The current event counter increments on register writebacks, so its printed CPI is not a complete architectural CPI measurement. Future work includes pipeline-valid retirement tracking, deeper verification, synchronous memory interfaces, and timing optimization.
